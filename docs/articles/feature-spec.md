# 記事表示機能仕様

## 1. 概要

`LifePlan` の ASP.NET Core MVC アプリに、microCMS で管理した記事を表示する機能を追加する。

記事本文・タイトル・URL用slug・説明文・サムネイル・カテゴリ・タグ・SEO 用説明文は microCMS を正とし、アプリ側は表示と導線を担当する。

## 2. 対象画面

| 画面 | パス案 | 説明 |
| --- | --- | --- |
| 記事一覧 | `/Articles` | 公開済み記事を新しい順に表示する |
| 記事詳細 | `/Articles/{slug}` | 指定した記事を表示する |

初期実装では記事一覧、カテゴリフィルタ、記事詳細を対象とする。記事検索、タグ絞り込み、関連記事表示、下書きプレビュー、カテゴリ別SEOページは対象外とする。

## 2.1 共通ナビゲーション

- 共通ヘッダーのナビゲーションに、記事一覧ページ `/Articles` へのリンクを追加する。
- リンク文言は「記事」とする。
- 表示位置は既存ヘッダーナビゲーション内とし、添付デザインのように「機能一覧」「FP相談」などの既存リンクと同列に配置する。
- 記事一覧ページまたは記事詳細ページを表示している場合は、必要に応じて現在位置が分かる表示状態を付与する。
- 初期実装ではフッターへの記事リンク追加は対象外とする。

## 3. microCMS API

### 3.1 一覧取得

```http
GET https://{serviceDomain}.microcms.io/api/v1/articles
X-MICROCMS-API-KEY: {apiKey}
```

初期実装では `limit=6` と `offset=(page - 1) * 6` を利用して、1ページ6件で取得する。

```http
GET https://{serviceDomain}.microcms.io/api/v1/articles?limit=6&offset=0
X-MICROCMS-API-KEY: {apiKey}
```

カテゴリフィルタが指定されている場合は、microCMS の `filters` を利用して該当カテゴリの記事だけを取得する。カテゴリ指定にはURL用slugを使い、アプリ側でslugからmicroCMSの日本語カテゴリ名へ変換する。

### 3.2 詳細取得

```http
GET https://{serviceDomain}.microcms.io/api/v1/articles?filters=slug[equals]{slug}&limit=1
X-MICROCMS-API-KEY: {apiKey}
```

`slug` は microCMS の記事フィールドとして管理するURL用文字列を利用する。`slug` は記事ごとに一意とし、詳細ページURL `/Articles/{slug}` の生成と詳細取得に利用する。

## 4. レスポンス項目

初期実装で利用する項目は以下とする。

| microCMS項目 | 用途 |
| --- | --- |
| `id` | microCMS の内部ID。必要に応じてログや内部参照に利用 |
| `slug` | 詳細ページURL生成、詳細取得 |
| `publishedAt` | 公開日表示 |
| `updatedAt` | 更新日表示が必要な場合に利用 |
| `title` | 一覧・詳細タイトル |
| `description` | 一覧の抜粋 |
| `thumbnail.url` | 一覧・詳細のサムネイル |
| `thumbnail.width` | 画像サイズ属性 |
| `thumbnail.height` | 画像サイズ属性 |
| `category` | カテゴリ表示。配列で返る場合も初期実装では先頭を主カテゴリとして扱う |
| `tags` | タグ表示。初期実装ではカンマ区切り文字列を trim して分割する |
| `body` | 詳細本文 HTML。アプリ側でサニタイズしてから表示する |
| `metaDescription` | 詳細ページの meta description |

## 5. 記事一覧UI仕様

### 5.1 画面全体

記事一覧ページは、スクリーンショットのデザインを基準に以下の構成とする。

- ページ背景は既存サイトの淡い暖色系背景に合わせる。
- メインコンテンツ幅は中央寄せとする。
- PC表示では、左側に記事一覧、右側にサイドバーを配置する2カラム構成とする。
- 左カラムには見出し、説明文、カテゴリフィルタ、記事カードグリッド、ページネーションを表示する。
- 右カラムにはシミュレーションCTA、新着記事、カテゴリ一覧を表示する。
- モバイル表示では、記事一覧の下にサイドバー要素を縦積みする。

### 5.2 ヘッダーエリア

- 見出しは「お役立ち記事」とする。
- 見出し左にアクセントラインを表示する。
- 説明文は「結婚・家計・子育てのお金にまつわる情報をわかりやすく解説」とする。

### 5.3 カテゴリフィルタ

- 見出し下にカテゴリフィルタを横並びのピル型ボタンで表示する。
- 表示するカテゴリはアプリ側の固定カテゴリ一覧から生成する。
- 選択中カテゴリは緑背景、未選択カテゴリは薄いグレー背景で表示する。
- 初期表示では「すべて」を選択状態にする。
- カテゴリフィルタはURL遷移として扱い、`a` 要素で実装する。
- 選択中カテゴリのリンクには `aria-current="page"` を付与する。
- カテゴリフィルタのURLは `/Articles?category={slug}` とする。
- ページング中にカテゴリが選択されている場合は `/Articles?category={slug}&page={page}` とする。

| 表示名 | slug |
| --- | --- |
| すべて | なし |
| 結婚・結婚式 | `marriage` |
| 家計管理 | `household-budget` |
| 家事 | `housework` |
| 子育て | `parenting` |
| その他 | `other` |

microCMS の `category` は日本語表示名を保持し、URLや内部フィルタではアプリ側の固定slugを使用する。表示名とslugの対応表はアプリ側の固定定義として管理する。

microCMS のレスポンスで `category` が配列になる場合でも、初期実装では1記事1カテゴリを基本とし、複数選択時は先頭のカテゴリを主カテゴリとして扱う。

### 5.4 記事カード

- PC表示では記事カードを2列グリッドで表示する。
- 1ページあたりの表示件数は6件とする。
- 記事カードには以下を表示する。
  - サムネイル画像
  - カテゴリラベル
  - タイトル
  - 説明文
  - 公開日
- サムネイルが未設定の場合の表示は未決とする。
- カテゴリラベルは淡いグリーン背景の小さなピルで表示する。
- タイトルと説明文はカード内に収まるように行数制限を行う。
- 記事カードをクリックすると記事詳細へ遷移する。
- 記事詳細URLは `/Articles/{slug}` とし、`slug` は microCMS の記事フィールドを利用する。
- 記事が0件の場合は、記事がまだないことを示す表示を出す。
- microCMS 取得に失敗した場合は、エラー詳細をユーザーへ露出せず、記事を読み込めない旨の表示に留める。

### 5.5 ページネーション

- 記事一覧の下部中央にページネーションを表示する。
- 現在ページは緑背景で表示する。
- ページ番号と次ページボタンを表示する。
- スクリーンショット上の表示例は `1`, `2`, `3`, `>` とする。
- ページ番号はURL遷移として扱い、`a` 要素で実装する。
- ページネーション全体は `nav` 要素で囲み、記事一覧のページ移動であることが分かる `aria-label` を付与する。
- 現在ページのリンクには `aria-current="page"` を付与する。
- URLは `/Articles?page={page}` を基本とする。
- カテゴリ選択中は `/Articles?category={slug}&page={page}` とする。
- `page` が未指定、または1未満の場合は1ページ目として扱う。
- `limit` は6件固定とする。
- `offset` は `(page - 1) * 6` とする。
- microCMS レスポンスの `totalCount` から総ページ数を算出する。
- 最終ページより大きい `page` が指定された場合は、1ページ目へ戻す。
- 前ページボタンは2ページ目以降で表示する。
- 次ページボタンは現在ページが最終ページより前の場合に表示する。
- 総ページ数が1以下の場合はページネーションを表示しない。

### 5.6 右サイドバー

#### シミュレーションCTA

- 右カラム上部に、ライフプランシミュレーションへのCTAを表示する。
- 背景は緑、内側に白いボタンを配置する。
- CTA文言は以下とする。
  - 見出し: `ふたりの将来のお金を見える化しませんか？`
  - ボタン: `無料でシミュレーション`
- CTAクリック時は `/LifePlan` へ遷移する。
- CTAは遷移リンクのため、`a` 要素で実装する。

#### 新着記事

- CTA下に「新着記事」枠を表示する。
- 新着記事は3件表示とする。
- 各行には小さなサムネイル、タイトル、公開日を表示する。
- 行クリックで記事詳細へ遷移する。
- サムネイルが未設定の場合はプレースホルダーを表示する。

#### カテゴリ一覧

- 新着記事の下に「カテゴリ」枠を表示する。
- カテゴリ名と記事件数を表示する。
- 記事件数は現在表示中ページの件数ではなく、全公開記事を対象にしたカテゴリ別件数とする。
- 件数は microCMS のカテゴリ絞り込みレスポンスの `totalCount` を利用して算出する。
- 表示カテゴリはカテゴリフィルタと同じ分類を基本とする。
- スクリーンショットでは各カテゴリ件数が右寄せで表示される。
- カテゴリクリック時は、カテゴリフィルタと同じ `/Articles?category={slug}` へ遷移する。
- カテゴリ一覧のリンクも `a` 要素で実装する。

### 5.7 カテゴリURL方針

カテゴリフィルタのURL形式は、カテゴリ表示名ではなく安定したカテゴリキーを使ったクエリ文字列形式とする。

```text
/Articles?category=household-budget&page=2
```

理由は以下とする。

- ASP.NET Core MVC の既存ルーティングに追加変更が少ない。
- ページ番号や将来の並び替え条件を同じURLで扱いやすい。
- 日本語カテゴリ名をURLに直接含めず、表示名変更の影響を避けられる。
- カテゴリページをSEO対象として強く育てる段階になったら、`/Articles/category/{slug}` 形式へ追加移行できる。

将来的にカテゴリ別ページを検索流入の入口として明確に扱う場合は、以下のようなパス形式を検討する。

```text
/Articles/category/household-budget
```

### 5.8 リンクとアクセシビリティ

- 画面遷移する要素は `a` 要素で実装する。
- 画面内の表示状態だけを変える要素は `button` 要素で実装する。
- 初期実装のカテゴリフィルタ、ページネーション、記事カード、CTA、新着記事、カテゴリ一覧はすべてURL遷移のため `a` 要素で実装する。
- 記事カードはカード全体をリンクにする場合でも、リンクテキストとして記事タイトルが読み上げられる構造にする。
- 画像だけに依存せず、記事タイトルやカテゴリ名のテキストで遷移先が分かるようにする。
- 装飾目的のプレースホルダー画像は、必要に応じて空の `alt` または `aria-hidden` を使い、記事タイトルの読み上げを妨げない。

## 6. 記事詳細UI仕様（仮）

記事詳細ページのデザインは未確定のため、初期実装では仮仕様として以下を採用する。詳細デザインが確定した時点で本節を更新する。

### 6.1 画面全体

- ページ背景は記事一覧ページと同じ淡い暖色系背景に合わせる。
- PC表示では、左側に記事本文、右側にサイドバーを配置する2カラム構成とする。
- 右サイドバーは記事一覧ページと同じシミュレーションCTA、新着記事、カテゴリ一覧を表示する。
- モバイル表示では、記事本文の下にサイドバー要素を縦積みする。
- 記事一覧へ戻るリンクを本文エリア上部または下部に表示する。

### 6.2 記事ヘッダー

- タイトルを詳細ページの `h1` として表示する。
- 公開日を表示する。
- `updatedAt` は初期実装では表示しない。
- カテゴリを表示する。
- タグがある場合は、カンマ区切り文字列を分割したタグ一覧を表示する。
- サムネイルがある場合はタイトル下に表示する。
- サムネイルが未設定の場合の表示は、一覧ページと同じく未決とする。

### 6.3 本文

- `body` を記事本文として表示する。
- 本文 HTML はサーバー側でサニタイズし、許可済み HTML だけを ViewModel に渡して表示する。
- View はサニタイズ済み本文 HTML のみ `Html.Raw` で表示し、microCMS の `body` を直接 `Html.Raw` に渡さない。
- サニタイズでは `script`、`iframe`、`style`、`onload`、`onclick` などの実行可能なタグ・属性を許可しない。
- 本文内の見出し、段落、リスト、リンク、画像、引用、コードブロックが崩れないように記事本文用のCSSを用意する。
- 本文下部にライフプランシミュレーションCTAを表示するかは未決とする。初期実装では右サイドバーCTAのみとする。

### 6.4 SEO

- `metaDescription` がある場合は `ViewData["Description"]` に設定する。
- `metaDescription` が未入力の場合は `description` を代替利用する。
- ページタイトルは記事タイトルを利用する。
- 記事詳細ページでは記事ごとの最小OGP metaを出力する。
- 記事詳細ページの `og:title` は記事タイトルを利用する。
- 記事詳細ページの `og:description` は `metaDescription` を優先し、未入力の場合は `description` を利用する。
- 記事詳細ページの `og:image` は `thumbnail.url` がある場合に利用する。
- 記事詳細ページの `og:type` は `article` とする。
- 記事詳細ページの `og:url` は現在の記事詳細URLを利用する。
- 記事一覧ページでは一覧ページ用の固定OGP metaを出力する。
- canonical、構造化データは初期実装では対象外とし、必要になった時点で追加する。

### 6.5 エラー時

- 指定した `slug` の記事が取得できない場合は、詳細なAPIエラーを表示せず、記事が見つからない旨を表示する。
- 見つからない表示には記事一覧へ戻るリンクを配置する。
- HTTPステータスは404を返す。

## 7. 設定値

| 設定キー | 例 | 用途 |
| --- | --- | --- |
| `MicroCms:ServiceDomain` | `futari-kakei` | microCMS サービスドメイン |
| `MicroCms:ApiKey` | `********` | APIキー |
| `MicroCms:ArticlesEndpoint` | `articles` | 記事APIのエンドポイント名 |

Azure App Service では `MicroCms__ServiceDomain` のように `__` 区切りで環境変数へ設定する。

## 8. セキュリティ

- APIキーはフロントエンドへ出さない。
- APIキーは Git 管理対象の設定ファイルへ書かない。
- 外部API呼び出しはサーバー側に閉じる。
- 本文 HTML はサーバー側でサニタイズしてから表示する。
- View で `Html.Raw` を使う場合は、サニタイズ済み本文 HTML に限定する。
- サニタイズの許可タグ・属性は allowlist として定義し、実行可能な HTML は許可しない。
