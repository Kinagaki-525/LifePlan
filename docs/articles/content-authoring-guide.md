# 記事作成ガイド

microCMS で記事を作成する際の入力ルールを管理する。

## 1. 対象API

- API名: `articles`
- 種類: リスト形式
- microCMS 一覧取得: `GET /api/v1/articles`
- アプリ側の詳細ページ: `/Articles/{slug}`
- microCMS 詳細取得: `GET /api/v1/articles?filters=slug[equals]{slug}&limit=1`

## 2. microCMS側の設定依頼

`articles` API に、記事詳細URL用の `slug` フィールドを追加し、`thumbnail` と `category` を必須項目にする。

- フィールドID: `slug`
- 表示名: `slug` または `URLスラッグ`
- 型: テキスト
- 必須: 必須
- 用途: 記事詳細ページURL `/Articles/{slug}` と、アプリ側の記事詳細取得に利用する
- 入力ルール: 英小文字、数字、ハイフンのみ
- 重複: 記事ごとに重複しない値にする

## 3. 入力項目

| 項目 | 型 | 必須 | 用途 |
| --- | --- | --- | --- |
| `title` | テキスト | 必須 | 記事タイトル、詳細ページの見出し |
| `slug` | テキスト | 必須 | 詳細ページURL、記事詳細取得キー |
| `description` | 複数行テキスト | 必須 | 一覧の抜粋 |
| `thumbnail` | 画像 | 必須 | 一覧・詳細のメイン画像 |
| `category` | 複数選択または配列 | 必須 | 記事カテゴリ表示 |
| `tags` | テキスト | 任意 | カンマ区切りのタグ表示 |
| `body` | リッチエディタ | 必須 | 記事本文 |
| `metaDescription` | テキスト | 任意 | meta description |

## 4. タイトル

- 検索結果やSNSで意味が伝わる具体的なタイトルにする。
- 長すぎるタイトルは一覧カードで折り返される前提とする。
- サービス名を毎回入れるかは運用で統一する。

## 5. slug

- SEO向けURLに使う英小文字・数字・ハイフンの文字列として入力する。
- 記事ごとに一意にする。
- 公開後は原則変更しない。変更すると既存URLが変わる。
- タイトルをそのまま日本語で入れず、内容が分かる短い英語表現にする。
- 空白、アンダースコア、日本語、記号は使わない。

例:

| 記事タイトル | slug例 |
| --- | --- |
| 家計管理の始め方 | `household-budget-start-guide` |
| 結婚前に話し合うお金のこと | `money-talk-before-marriage` |
| 子育て費用の基本 | `childcare-cost-basic` |

## 6. description

- 一覧画面に表示する短い説明文として使う。
- 目安は80〜160文字程度。
- 本文冒頭の長文をそのまま入れず、記事の要点が伝わる文章にする。
- 改行や箇条書きは入れず、一覧カードで読みやすい1段落にする。

## 7. thumbnail

- すべての記事に必ず設定する。
- 横長画像を推奨する。
- 未設定の記事は公開前チェックで修正する。

## 8. category

- 初期実装では表示とカテゴリフィルタに利用する。
- すべての記事に必ず設定する。
- カテゴリページをSEO対象として独立させることは初期実装の対象外。
- 同じ意味の表記ゆれを避ける。
- microCMS 側では日本語のカテゴリ名を保持する。
- カテゴリURLで使うslugはアプリ側の固定対応表で管理する。
- microCMS のレスポンスが配列になる場合でも、初期実装では1記事1カテゴリを基本とする。
- 入稿時は1記事1カテゴリに揃える。
- 複数カテゴリを選択した場合、アプリ側では先頭のカテゴリを主カテゴリとして扱う方針とする。
- 初期実装で利用するカテゴリは以下とする。

| 表示名 | slug |
| --- | --- |
| 結婚・結婚式 | `marriage` |
| 家計管理 | `household-budget` |
| 家事 | `housework` |
| 子育て | `parenting` |
| その他 | `other` |

## 9. tags

- 初期実装では `家計管理,ライフプラン,共働き` のようなカンマ区切り文字列として扱う。
- カンマの前後に空白が入っても、アプリ側で trim する。
- 表記ゆれを避ける。例: `ライフプランシミュレーション` を使い、`ライフプランシュミレーション` は使わない。
- 将来的にタグページを作る場合は、microCMS 側のフィールド型を見直す。

## 10. body

- 本文はHTMLとしてアプリに渡される。
- アプリ側では本文HTMLをサニタイズし、許可済みHTMLだけを表示する。
- ボタンやリンクを入れる場合は、リンク先URLと表示文言を公開前に確認する。
- 本文内画像は利用できる。ただし横幅が大きすぎる画像は表示崩れの原因になるため、本文幅に収まる画像を使う。
- `script`、`iframe`、`style`、フォーム要素、イベント属性など、実行可能または画面挙動を持つHTMLは使わない。入力されてもアプリ側のサニタイズで除去される。
- 画像やリンクURLには `javascript:` や `data:` を使わず、通常の `https` URLを使う。
- シミュレーションへの導線は、可能なら本文内HTMLに直接書くより、アプリ側の共通CTAとして追加することを検討する。
- HTMLタグを本文に文字として貼り付けない。リッチエディタ上でリンクや見出しを設定する。
- コードブロックはコード説明が目的の場合だけ使う。CTAボタンを作る目的でHTMLコードをコードブロックに入れない。
- 見出しは太字・下線の段落ではなく、リッチエディタの見出しを使う。
- 箇条書きは通常の段落を並べず、リッチエディタのリスト機能を使う。
- 空の段落は入れない。

## 11. metaDescription

- 記事詳細ページの `meta description` に使う。
- 未入力の場合は `description` を代替利用する。
- 目安は80〜160文字程度。

## 12. 公開前チェック

- タイトル、slug、description、metaDescription に誤字がない。
- slug が英小文字・数字・ハイフンのみで、記事ごとに重複していない。
- description は一覧用の短い1段落になっている。
- サムネイルが表示意図に合っている。
- カテゴリが設定されている。
- カテゴリ・タグの表記ゆれがない。
- 本文内リンクが正しいURLを指している。
- 本文内画像が表示意図に合っている。
- 本文内にHTMLタグが文字として表示されていない。
- CTA用HTMLがコードブロックとして入っていない。
- 本文内にAPIキーや個人情報などの機密情報が含まれていない。
- 本文内に実行可能なHTMLが含まれていない。
