# 記事作成ガイド

microCMS で記事を作成する際の入力ルールを管理する。

## 1. 対象API

- API名: `articles`
- 種類: リスト形式
- アプリ側の一覧取得: `GET /api/v1/articles`
- アプリ側の詳細取得: `GET /api/v1/articles/{id}`

## 2. 入力項目

| 項目 | 型 | 必須 | 用途 |
| --- | --- | --- | --- |
| `title` | テキスト | 必須 | 記事タイトル、詳細ページの見出し |
| `description` | 複数行テキスト | 必須 | 一覧の抜粋 |
| `thumbnail` | 画像 | 任意 | 一覧・詳細のメイン画像 |
| `category` | 複数選択または配列 | 任意 | 記事カテゴリ表示 |
| `tags` | テキスト | 任意 | カンマ区切りのタグ表示 |
| `body` | リッチエディタ | 必須 | 記事本文 |
| `metaDescription` | テキスト | 任意 | meta description |

## 3. タイトル

- 検索結果やSNSで意味が伝わる具体的なタイトルにする。
- 長すぎるタイトルは一覧カードで折り返される前提とする。
- サービス名を毎回入れるかは運用で統一する。

## 4. description

- 一覧画面に表示する短い説明文として使う。
- 目安は80〜160文字程度。
- 本文冒頭の長文をそのまま入れず、記事の要点が伝わる文章にする。

## 5. thumbnail

- 可能ならすべての記事に設定する。
- 横長画像を推奨する。
- 画像が未設定でも画面が壊れないようにアプリ側でフォールバックを用意する。

## 6. category

- 初期実装では表示のみ行う。
- カテゴリページや絞り込みは初期実装の対象外。
- 同じ意味の表記ゆれを避ける。

## 7. tags

- 初期実装では `家計管理,ライフプラン,共働き` のようなカンマ区切り文字列として扱う。
- カンマの前後に空白が入っても、アプリ側で trim する。
- 将来的にタグページを作る場合は、microCMS 側のフィールド型を見直す。

## 8. body

- 本文はHTMLとしてアプリに渡される。
- ボタンやリンクを入れる場合は、リンク先URLと表示文言を公開前に確認する。
- `script` タグやイベント属性など、実行可能なHTMLは使わない。
- シミュレーションへの導線は、可能なら本文内HTMLに直接書くより、アプリ側の共通CTAとして追加することを検討する。

## 9. metaDescription

- 記事詳細ページの `meta description` に使う。
- 未入力の場合は `description` を代替利用する方針を検討する。
- 目安は80〜160文字程度。

## 10. 公開前チェック

- タイトル、description、metaDescription に誤字がない。
- サムネイルが表示意図に合っている。
- カテゴリ・タグの表記ゆれがない。
- 本文内リンクが正しいURLを指している。
- 本文内にAPIキーや個人情報などの機密情報が含まれていない。
- 本文内に実行可能なHTMLが含まれていない。
