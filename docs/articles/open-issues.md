## 決定済み

- microCMS へのアクセスはサーバー側で行う。
- APIキーは環境変数または User Secrets で管理する。
- ブラウザ側 JavaScript に APIキーを渡さない。
- 記事本文HTMLはサーバー側でサニタイズし、許可済みHTMLだけを ViewModel に渡す。
- 記事詳細Viewでは、サニタイズ済み本文HTMLのみ `Html.Raw` で表示する。
- 記事詳細URLは `/Articles/{slug}` とし、`slug` は microCMS の記事フィールドを利用する。
- microCMS の `articles` API に、必須かつ記事ごとに一意の `slug` フィールドを追加する。
- 共通ヘッダーのナビゲーションに `/Articles` への「記事」リンクを追加する。
- 初期実装ではフッターへの記事リンク追加は対象外とする。
- 記事一覧は1ページ6件表示とする。
- カテゴリフィルタは初期実装に含める。
- カテゴリフィルタURLは `/Articles?category={slug}&page={page}` とする。
- microCMS の `category` は日本語表示名を保持し、URL用slugはアプリ側の固定対応表で管理する。
- 右サイドバーのカテゴリ件数は、現在ページ内ではなく全公開記事を対象に集計する。
- 右サイドバーのカテゴリ一覧クリック時は、カテゴリフィルタと同じURLへ遷移する。
- `tags` は microCMS 側ではカンマ区切り文字列として管理し、アプリ側で trim して分割する。
- 右サイドバーCTAのリンク先は `/LifePlan`、ボタン文言は「無料でシミュレーション」とする。
- 新着記事は3件表示とする。
- モバイル表示では、サイドバーを記事一覧の下に縦積みする。
- 記事詳細ページは仮仕様として、一覧ページと同じ右サイドバーを表示する。
- 記事詳細ページでは、`metaDescription` が未入力の場合に `description` を代替利用する。
- 存在しない `slug` の記事詳細は HTTP 404 を返し、画面には記事が見つからない旨と記事一覧へ戻るリンクを表示する。
- 初期実装では microCMS API 取得結果のキャッシュは導入せず、リクエストごとに取得する。
- 記事詳細ページでは記事ごとの最小OGP metaを出力する。
- 記事一覧ページでは一覧ページ用の固定OGP metaを出力する。
- canonical、構造化データは初期実装では対象外とする。

## 懸念事項

- キャッシュなしのため、アクセス数が増えると microCMS API 呼び出し回数が増える。
- キャッシュなしのため、表示速度が microCMS API の応答速度に影響されやすい。
- microCMS API に一時的な障害や遅延がある場合、記事一覧・詳細表示に影響する可能性がある。
- アクセス数やレスポンス速度の課題が見えた時点で、`IMemoryCache` または CDN を含めてキャッシュ導入を検討する。
