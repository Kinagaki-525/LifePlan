# レビュー・テスト観点

すべての変更に全項目を要求せず、変更した振る舞いと影響範囲から確認対象を選ぶ。

| 観点 | 確認すること | テスト例 |
| --- | --- | --- |
| 正常系 | 仕様どおりの入力・処理・出力、既定値 | 代表的な入力と仕様から求めた期待値 |
| 異常系 | 不正入力、例外、依存先の失敗と復旧 | 不正形式、404・500、タイムアウト、キャンセル |
| 境界値・同値分割 | 範囲の包含、空と未指定の違い、桁数 | 最小・最大、その直前直後、0、負数、空、null |
| 条件・分岐 | 条件の組み合わせと無効項目の扱い | 開始＝終了、開始＞終了、任意項目の有無 |
| 計算・変換 | 単位、丸め、精度、順序、オーバーフロー | 円と万円、月額と年額、利率0%、端数 |
| 結合・契約 | 層間の型、DI、HTTPパラメータ、応答形式 | Mapperの往復、クエリ、状態コード、ページ境界 |
| 回帰 | 変更前の利用ケース、既存の呼び出し元 | 修正した不具合を再現するテスト、関連機能 |
| UI | 入力保持、エラー表示、画面状態、アクセシビリティ | POST失敗後、タブ切替、キーボード操作、ARIA |
| 基本的な安全性 | サーバー側検証、認可、エスケープ、秘密情報 | 検証を回避したPOST、HTML、URL、ログ出力 |
| 性能・資源 | 変更で増えた通信、無制限処理、資源の解放 | API呼び出し回数、大量入力、HttpResponseの破棄 |
| テスト品質 | 失敗すべき変更で失敗するか、再現性、独立性 | 固定時刻、通信の代替、順序非依存、観測可能な結果 |

単体テストは純粋な計算・判定を、結合テストは受け渡しやフレームワークとの接続を、UI確認はユーザー操作と表示を検証する。実HTTP・ブラウザを使っていないテストを、それらの実環境での検証済みとして報告しない。

テストが不足している場合は、正常系を追加するだけで足りるのか、境界値・異常系・回帰テストが必要かを具体化する。新しいテスト基盤の導入は、既存基盤で確認できない必要性がある場合に提案する。
