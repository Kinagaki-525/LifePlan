# Quickstart: iOS端末でフォーム操作時に画面が自動拡大される問題の解消の検証

対象の部品と文字の大きさは [data-model.md](data-model.md)、CSS の約束は [contracts/form-controls.md](contracts/form-controls.md)、判定と検証方法の根拠は [research.md](research.md) を参照する。

## 1. ビルドとテスト

```powershell
dotnet build LifePlan.slnx -m:1
dotnet test LifePlan.slnx -m:1
```

- 期待結果：ビルドは警告・エラーなし、既存テストはすべて合格する（SC-007）。C# は変更しない。
- Visual Studio のデバッガーで実行中は DLL がロックされる。その場合は `--artifacts-path <一時フォルダ>` を付けて別の出力先で実行する。

## 2. 自動確認（Edge headless。research.md R5）

アプリを起動し（`http://localhost:5250`）、次のページの HTML を取得する。

- `/LifePlan`（入力画面）
- `/LifePlan` で試算した結果画面（「表示する年度」選択欄を含む）
- `/Contact`

- 入力エラーの画面（シミュレーター、お問い合わせ）

結果画面と入力エラーの画面は、POST で表示する（偽造防止トークンが必要）。GET と POST に同じセッションを使い、入力画面の値とトークンをそのまま送る。手順は tasks.md T002 を参照する。お問い合わせは、必須項目を空にして入力検証で止め、送信処理まで進めない（開発環境でもメールが送られるため）。

取得した HTML に、`<base href>` と計測用のスクリプトを足してスクラッチに置く。リポジトリには含めない。計測用のスクリプトは、対象の部品（[contracts/form-controls.md](contracts/form-controls.md)）ごとの計算後の文字の大きさと、`document.documentElement.scrollWidth` を DOM に書き出す。

| # | 条件 | 画面幅 | 期待結果 | 対応 |
| --- | --- | --- | --- | --- |
| A1 | タッチ相当（`--blink-settings=primaryPointerType=2,availablePointerTypes=2,primaryHoverType=1,availableHoverTypes=1`） | 320 / 375 / 390 / 430 / 667 / 852 / 1024 | 対象の 75 個がすべて 16px。チェックボックスは対象外で変わらない | FR-001〜003、FR-009 |
| A2 | タッチ相当 | A1 と同じ | ラベル・単位・補足文・エラー文の文字の大きさが修正前と同じ | FR-009、FR-011 |
| A3 | タッチ相当 | 320 / 375 / 390 / 430 / 667 / 852 | ページの横幅が画面幅を超えない（横スクロールなし） | FR-008、SC-004 |
| A4 | PC 相当（起動オプションなし） | 375 / 1280 | 対象の部品の文字の大きさが修正前と同じ（375px：12.25px / 14px、1280px：14px / 16px） | FR-012、SC-006 |
| A5 | PC 相当 | 375 / 1280 | 修正前後のスクリーンショットに差がない | SC-006 |

- Edge headless はウィンドウ幅を約 500px 未満にできないため、指定した幅の `iframe` に検証用 HTML を読み込んで計測・撮影する。シミュレーター入力画面は、すべてのタブを表示した状態で計測する（research.md R5）。
- 起動オプションでタッチを再現できない（A1 で `matchMedia('(pointer: coarse)').matches` が `false`）場合は、Edge の開発者ツールのデバイスモード（タッチあり）で A1〜A3 を手動で確認する。
- 修正前の値は、`develop`（`2f48e21`）で同じ計測をして記録しておく。

## 4. 実機確認（自動拡大の症状）

自動拡大は iOS の実機でしか再現できない。各端末で、画面を等倍にしてから操作する。

### 実機からの接続（同じ Wi-Fi のネットワーク内）

1. PC で `dotnet run --project LifePlan/LifePlan.csproj --launch-profile http --urls http://0.0.0.0:5250` を実行する（開発環境として起動する）。
2. PC の IP アドレスを `ipconfig` で調べる（例：`192.168.1.23`）。
3. 初回は、Windows ファイアウォールの確認画面で「プライベートネットワーク」だけを許可する。確認画面が出ない場合は、管理者の PowerShell で次を実行し、確認が終わったら削除する。
   - 追加：`New-NetFirewallRule -DisplayName "LifePlan dev 5250" -Direction Inbound -Protocol TCP -LocalPort 5250 -Profile Private -Action Allow`
   - 削除：`Remove-NetFirewallRule -DisplayName "LifePlan dev 5250"`
4. 実機のブラウザで `http://<PC の IP アドレス>:5250/LifePlan` を開く。
5. 確認が終わったらアプリを止める。手順 3 でルールを追加した場合は削除する。

- 公衆 Wi-Fi では行わない。インターネットに公開する方法（トンネルなど）は使わない。
- 接続できない場合（ルーターの端末間通信の制限など）は、実機の結果を「未確認」として記録し、配置後の検証環境で確認する。

### 確認項目

| # | 端末・ブラウザ | 操作 | 期待結果 | 対応 |
| --- | --- | --- | --- | --- |
| D1 | iPhone・Safari（縦向き、横向き） | シミュレーターの入力欄 32 個・選択欄 36 個（子どもの年齢を入れて、教育プランの欄を操作できる状態にする）、結果画面の「表示する年度」、お問い合わせの 6 個を順にタップする。縦向きで確認した後、横向きに回してから続けてタップする | 倍率が 1 回も変わらない（75 個 × 2 向き） | FR-001、FR-002、SC-001 |
